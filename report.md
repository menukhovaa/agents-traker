## 1. Цель и исходные условия

Сравнить разработку одного автономного мини-трекера в двух подходах при одинаковой модели и одинаковых сценариях проверки. Для каждой задачи используются `id`, `title`, `hours`, `done`. Исходные данные: «Чтение» — 2 ч, готово; «Практика» — 4 ч, активно; «Повторение» — 2 ч, активно. Общие ожидания: **8 ч всего, 2 ч выполнено, 25% прогресса по часам**. После выполнения «Практики» — **6/8 ч и 75%**.

Первой попытке задаётся короткий запрос. Во второй сначала формируются `proposal.md`, `specs/tracker/spec.md`, `design.md`, `tasks.md`, затем реализуется `tracker-v2.html`. Формально задание требует два независимых чата одной модели. Две версии HTML и четыре документа были предоставлены пользователем; **раздельность чатов и число промежуточных запросов по одним файлам независимо не подтверждаются**. Проверка исходит из того, что это представленные результаты двух подходов; скриншоты диалогов не проверялись.

**Исходные HTML и четыре документа спецификации сохранены без изменения кода или содержания.** Им присвоены нормализованные имена файлов для репозитория.

## 2. Как проверяли

Автоматизированные проверки выполнены в **Chromium (headless) через Python Playwright**. Браузер в данной среде заблокировал прямую навигацию по `file://`, поэтому оригинальный текст каждого HTML загружался через `page.set_content`. Для основных тестов применён простой **тестовый заменитель localStorage в памяти**; это позволяет воспроизвести начальное состояние, не меняя код приложений. Отдельно проверено поведение при недоступном native localStorage (без заменителя). Каждый независимый тест выполнялся на свежей странице с исходными тремя задачами. Результаты и скриншоты находятся в `evidence/`.

Отсутствие горизонтальной прокрутки проверено при viewport 390 px. Прямое открытие файлов двойным щелчком на личном компьютере, постоянство хранения между отдельными запусками браузера и работа в других браузерах **не проверялись**.

### Подробнее об ошибках V1

1. **Неправильная база процента.** В функции `updateStats()` V1 использует долю завершённых *задач*: `Math.round(doneTasks.length / tasks.length * 100)`, вместо суммы *часов* завершённых задач, делённой на часы всех задач. Поэтому получены 33% и 67% вместо 25% и 75%.
2. **Валидация часов не соответствует общей приёмке.** В V1 разрешён шаг 0,25 и диапазон 0,25–100000, поэтому значения 0,25, 0,75 и 24,5 успешно добавляют задачу, хотя по общим проверкам допустимы только 0,5–24 с шагом 0,5.
3. **Нет постоянного текста ошибки возле поля.** Отправка пустых или отрицательных значений блокируется проверками формы браузера либо JavaScript, но отдельные встроенные сообщения рядом с полями не отображаются. Поля при таких ошибках сохраняют введённые значения.

V1 является реализацией более короткого промпта, который не уточнял все эти ограничения. Это именно наблюдаемое расхождение с **общими критериями приёмки**, а не обвинение в невыполнении явно сообщённых V1 требований.

### Дополнительные проверки

- **Адаптивность 390 px:** PASS для обеих версий. У `document.documentElement.scrollWidth` значение 390 px, горизонтального переполнения в исследованном состоянии нет. Скриншоты — `evidence/v1-mobile.png` и `evidence/v2-mobile.png`.
- **Недоступность хранилища в тестовой среде:** обе версии продолжают показывать задачи. V2 показывает пользователю отдельное предупреждение, V1 — нет; в V1 предусмотрен только `console.warn`.
- **Неперехваченные ошибки JavaScript:** не обнаружены в выполненных браузерных сценариях.
- **Локальные ресурсы:** в обоих исходных HTML встроены CSS и JavaScript; ссылки на CDN и сторонние библиотеки не нужны.

## 6. Вывод и ограничения

В данном конкретном сравнении реализация после подробной спецификации прошла все обязательные проверки (5/5), тогда как прямая реализация — только 1/5. Самое существенное различие — правильный подсчёт процента **по часам**, а не по количеству задач; спецификация отдельно фиксировала этот расчёт, граничные значения и ошибки ввода.

Однако это **одно сравнение двух исходов**, а не доказательство, что OpenSpec всегда улучшает код. Прямому запросу не давали подробных правил приёмки; часть дефектов могла быть предотвращена более точным обычным промптом. Вариант A использует формат документов OpenSpec **без CLI или структурного валидатора**. Проверки интерфейса охватывали только Chromium и одну узкую ширину. Данные о стоимости, токенах и времени создания отсутствуют.
