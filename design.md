# Design: Мини-трекер

## 1. Модель данных

Задача представляется объектом с четырьмя полями:

| Поле | Тип | Ограничения |
|---|---|---|
| id | string | Уникальное значение |
| title | string | Непустое после trim |
| hours | number | 0,5–24; шаг 0,5 |
| done | boolean | true / false |

Основное состояние приложения — массив задач.

Дополнительное состояние интерфейса:
- Текущий фильтр: all / active / done.
- Значения полей формы.
- Ошибки валидации.
- Сообщение о недоступности localStorage, если используется сохранение.

## 2. Операции с данными

### Добавление

1. Получить название и часы из формы.
2. Проверить значения.
3. Если есть ошибки, показать их без очистки формы.
4. Если данные корректны, создать задачу с уникальным id и done=false.
5. Добавить задачу в массив.
6. Обновить интерфейс и расчёты.

### Удаление

1. Получить id удаляемой задачи.
2. Удалить задачу из массива.
3. Обновить список и расчёты.

### Переключение done

1. Найти задачу по id.
2. Изменить done на противоположное значение.
3. Обновить список и расчёты.

## 3. Валидация

### Название

- Удалить пробелы в начале и конце через trim.
- Проверить, что результат непустой.
- Сохранять валидное название без крайних пробелов.

### Часы

- Сначала проверить наличие введённого значения.
- Затем проверить возможность преобразования в конечное число.
- Проверить диапазон 0,5–24 включительно.
- Проверить кратность 0,5.
- Не заменять пустое значение на ноль.

При неуспешной проверке исходные значения формы сохраняются, а сообщение показывается возле проблемного поля.

## 4. Расчёты

Обозначения:

- H — сумма hours всех задач.
- D — сумма hours задач с done=true.
- P — процент выполнения.

Формулы:

H = Σ hours

D = Σ hours, где done=true

Если H > 0:

P = round(100 × D / H)

Если H = 0:

P = 0

### Пример

Начальные задачи:

- Чтение: 2 ч, готово.
- Практика: 4 ч, активно.
- Повторение: 2 ч, активно.

Получаем:

H = 2 + 4 + 2 = 8

D = 2

P = round(100 × 2 / 8) = 25%

После выполнения «Практики»:

D = 2 + 4 = 6

P = round(100 × 6 / 8) = 75%

При отсутствии задач:

H = 0, D = 0, P = 0.

## 5. Фильтрация

Фильтр формирует отображаемую выборку из общего массива задач.

| Фильтр | Условие |
|---|---|
| all | Все задачи |
| active | done=false |
| done | done=true |

Исходный массив не изменяется при переключении фильтров.

Все показатели вычисляются исключительно по исходному массиву, а не по отфильтрованной выборке.

## 6. Архитектура A

Файл: `tracker-v2.html`.

Включает:
- HTML-разметку формы, списка, фильтров и показателей.
- Встроенные CSS-стили.
- Встроенный JavaScript для состояния, обработки действий, валидации и расчётов.

Не требует подключения дополнительных файлов.

## 7. Архитектура B

- `index.html`: структура интерфейса.
- `styles.css`: адаптивное оформление.
- `app.mjs`: состояние интерфейса, события, отображение.
- `domain.mjs`: операции с задачами, валидация и вычисления.
- `tests/acceptance.test.mjs`: приёмочные проверки.

Логика в domain.mjs должна быть отделена от DOM, чтобы расчёты и операции можно было тестировать самостоятельно.

Тесты используют встроенные возможности среды выполнения JavaScript без установки внешних библиотек.

## 8. Обновление интерфейса

После изменения данных:

1. Определить задачи, видимые с текущим фильтром.
2. Обновить отображаемый список.
3. Пересчитать H, D и P по всем задачам.
4. Обновить показатели.

## 9. Адаптивность

На ширине 390 px:
- Содержимое помещается в доступную ширину.
- Поля и кнопки остаются читаемыми.
- Элементы при необходимости переносятся или располагаются вертикально.
- Горизонтальная прокрутка отсутствует.

## 10. Необязательный localStorage

При наличии сохранённых задач они загружаются при запуске; иначе используется стартовый пример.

Изменения задач сохраняются в localStorage.

Ошибки чтения и записи обрабатываются без остановки приложения. При сбое данные остаются доступны в памяти до завершения текущей сессии, а пользователю показывается уведомление.
